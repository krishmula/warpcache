Visual companion to docs/learning-roadmap.md. Written October 17, 2026. Class completion November 5.

1. The replanned schedule

Each bar is a phase. The diamonds are gates. Every gate has a fallback that still produces a complete submission.

2. Where the hours go

About 70 hours over three weeks. Learning is front-loaded. Building is most of Phases 1 and 2.

3. The one idea: decode attention is memory bound

One layer of Qwen3-1.7B history at 16K context, batch 1, on an RTX 4090. The whole project follows from these three numbers.

4. GPU execution model (concept C1)

A kernel launch is a grid of blocks. Each block is a set of threads that run on one streaming multiprocessor (SM) and share fast memory. Threads execute in warps of 32 lanes that run the same instruction together.

5. Memory hierarchy with numbers (concept C2)

Approximate RTX 4090 figures. The kernel lives in the bottom row. Registers hold q and the running state. The block touches shared memory once, for the final merge.

6. Paged cache layout (concept C6)

Tokens live in pages of 16. A request's block table lists its physical pages in order. The kernel never sees a contiguous history.

7. Path A vs Path B thread mapping

Path A gives one block the whole history. Path B gives each block a chunk, and a second kernel merges the chunks. The inner loop is identical. Write it once as a device function with a token range.

8. Why the selector exists: blocks vs SMs

Path A blocks for Qwen3-1.7B (16 query heads) at each batch size, against 128 SMs on the 4090. Below the line the blocks cannot fill the chip and Path B should win. This is the prediction the Phase 2 chunk sweep tests.

9. What to learn before each piece

Read a row only when you reach its first piece. Reading ahead past one phase is the most common way to lose a day.
